# J05 · 楼盘解读后推荐追问

> 建议输出契约；最多 3 个与“先验证后展示”沿用既有流程的统一设计。示例为测试对象。

## 职责与触发

JCHECK 已通过，或 JLIMIT 已输出受限说明后，根据当前项目的实际数据提供可继续查询的候选。不能重复邀请用户解读仍缺少资料的问题。

## 输入

- 当前项目、原问题、已回答的关注点。
- 可用字段、缺失字段、业务支持的操作与真实路径。
- 已展示问题，用于避免重复。

## AI 输出 JSON 示例

```json
{
  "node_id": "J05",
  "candidate_questions": [
    {
      "question": "这个楼盘还有哪些户型？",
      "project_ref": "demo-project-a",
      "focus": ["unit_types"],
      "required_fields": ["unit_types"],
      "verification_state": "pending_system_query"
    }
  ],
  "next_node": "JV"
}
```

## 字段说明与约束

- `candidate_questions` 可为空，不凑足数量；当前项目不静默替换。
- `required_fields` 必须是业务支持的字段；不能推荐无数据的通勤、学区或投资收益问题。
- `verification_state` 固定为待系统校验。JV 实际查询确认当前项目仍存在且具备支撑信息，最多展示 3 个。
- 所问资料缺失时，可保留真实详情/顾问入口；不可再次推荐同一个无法回答的问题。
- 用户点击后携带项目上下文进入 J01/J02；明确改问其他项目或业务时重新路由。

## 失败处理与验收

生成失败或验证全部失败时隐藏推荐区，保留已成功的解读与卡片。只有两条验证通过就展示两条；户型数据为空时不展示户型解读问题；离开详情 1 天内返回恢复会话。

## 依据

需求 §2.4.1 下一步推荐问题、§2.4.2 真实数据与零结果验证、§2.4.4 会话保持；本次楼盘解读细化。
