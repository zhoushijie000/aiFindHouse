# J02 · 楼盘对象与解读关注点

> 建议输出契约；示例引用由演示业务系统提供，不代表真实楼盘。

## 职责与触发

已识别 PROJECT_QUERY 后，提取用户指定项目、指代对象及想了解的内容。AI 负责理解表达；唯一项目 ID 的解析由系统 JRES 完成。

## 输入

- 当前问题、上轮项目引用、当前已选卡片或详情页上下文。
- 系统支持字段：基础信息、价格口径、户型、区位、配套、容积率、绿化率、取证、在售等。
- 历史引用是否仍有效，以及本轮是否明确切换项目。

## AI 输出 JSON 示例

演示上下文已提供 `demo-project-a`，用户问“它的户型呢？”：

```json
{
  "node_id": "J02",
  "target": {
    "provided_project_ref": "demo-project-a",
    "name_text": null,
    "reference_basis": "current_selected_card"
  },
  "focus": ["unit_types"],
  "original_question": "它的户型呢？",
  "target_changed": false,
  "unresolved": [],
  "next_node": "JRES"
}
```

## 字段说明

| 字段 | 说明 |
| --- | --- |
| `provided_project_ref` | 只能引用系统已提供的项目，不由 AI 编造 ID。 |
| `name_text` | 用户原文中的楼盘名或别名，未提供则为空。 |
| `reference_basis` | 本轮明示、所选卡片或有效历史上下文。 |
| `focus` | 用户关注的字段；“怎么样”可记为 overview，具体概况范围由已获数据决定。 |
| `target_changed` | 是否显式改问另一项目；改变后须重新匹配。 |
| `unresolved` | 不明确的名称、指代或关注点。 |

## 约束与系统衔接

- 用户新名称优先于历史对象；“它”只能继承明确、有效的指代。
- 不能按相似名称、推广优先级或热度替用户选项目。
- JRES 查询业务字典：唯一匹配才进 JQ；无指代或多候选进 J03；真实零匹配进 JNF。
- 对象解析接口异常走 JMATCHERR，重试对象匹配；详情获取异常走 JE1，重试详情接口。无效 AI 结构走 AI 重试，均不能按零匹配处理。

## 验收

- 上轮 A、本轮“B 的价格呢” → 改为 B，关注价格，重新解析。
- 同名项目位于不同区域 → 返回歧义，系统提供候选后补问。
- 已知项目但没有所问字段 → 后续走资料不足，不把问题改成找其他项目。

## 依据

H01 的 PROJECT_QUERY 定义与上下文规则；需求 §2.4.2 条件体系、真实数据与上下文能力。本次细化对象消歧为建议。
