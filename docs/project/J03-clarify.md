# J03 · 楼盘对象确认追问

> 建议输出契约。候选均需来自系统真实查询，示例仅说明格式。

## 职责与触发

系统无法确认唯一楼盘时，追问缺失名称或请用户从重名候选中选择。业务意图已明确，不使用“意图未识别”固定引导。

## 输入

- 原问题、已识别关注点、歧义原因。
- 系统查询返回的候选项目及可核实的名称、区域、ID。

## AI 输出 JSON 示例

```json
{
  "node_id": "J03",
  "question": "你想了解哪个楼盘？可以告诉我楼盘名称，或者在已有项目卡片中选择一个。",
  "candidate_refs": [],
  "awaiting": "project_target",
  "preserve_focus": ["overview"],
  "next_node": "JU1"
}
```

## 字段说明与约束

- `question`：简短、只问必要信息；不同时收集找房预算等无关条件。
- `candidate_refs`：仅从系统候选中引用，前端用真实名称、区域展示。
- `preserve_focus`：保留原解读问题，用户选完项目无需重复提问。
- 多个候选时提示选择；候选为空且属于缺名称时询问名称。已知名称但查询零匹配由 JNF 固定提示处理。
- 用户补充后回 J02/JRES；仍歧义继续确认，不猜测、不循环重复已确认字段。

## 失败处理与验收

AI 失败进入 JE2；已确认上下文不清空。两项目同名时必须展示真实候选；用户选定后只查询选中项目；明确改问政策时回 J01 重新路由。

## 依据

需求 §2.4.2 条件补充、上下文能力；楼盘解读对象确认属于本次新增建议。
