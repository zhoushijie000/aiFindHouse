# J04 · 基于真实项目数据解读楼盘

> 建议输出契约。以下项目名称、数值及引用全部为虚构测试数据，不构成真实楼盘推荐。

## 职责与触发

系统已确认唯一项目并完成 JQ、JSOURCE、JD2 后，基于本轮有效资料解释用户关注点。普通回复采用“核心概况 + 关注点说明 + 待核实项 + 详情入口”，建议 50–150 字。

## 输入

- 已确认项目与用户问题、关注点。
- 业务系统返回的结构化字段、单位、口径、更新时间、来源引用。
- 系统标注的缺失或冲突字段、真实详情与顾问路径引用。

## AI 输出 JSON 示例

测试输入仅提供楼盘 A 的三室户型和约 100–120㎡面积区间，不提供价格：

```json
{
  "node_id": "J04",
  "project_ref": "demo-project-a",
  "summary": "当前资料显示，示意楼盘 A 有三室户型，建筑面积约为100—120平方米。本次未取得对应房源的有效价格数据，具体户型分布和价格可进入楼盘详情查看或联系顾问核实。",
  "focus_points": [
    {"text": "有三室户型，建筑面积约100—120平方米。", "field_refs": ["unit_types", "unit_area_range"]}
  ],
  "unverified_items": ["当前对应房源价格"],
  "detail_route_ref": "demo-detail-route",
  "claims": [
    {"text": "三室", "field_ref": "unit_types"},
    {"text": "100—120平方米", "field_ref": "unit_area_range"}
  ],
  "next_node": "JCHECK"
}
```

## 字段说明

| 字段 | 说明 |
| --- | --- |
| `project_ref` | 当前已确认的真实项目引用。 |
| `summary` | 用户可见的简短解读，不展开长篇泛化分析。 |
| `focus_points` | 每项说明绑定本轮字段引用。 |
| `unverified_items` | 缺失或冲突信息明确列为待核实，不由模型补齐。 |
| `detail_route_ref` | 仅引用输入提供的有效详情入口。 |
| `claims` | 用于系统校验数字、单位、对象及业务来源。 |

## 约束与系统衔接

- 项目基本信息、价格、户型、容积率、绿化率、取证、在售、剩余房源等只能引用实际数据。
- 回答价格必须注明输入中已有的单价/总价/起价口径，不能互相替换；无面积条件不能推算总价。
- 区位配套只说明已核实的信息；无地图能力不计算通勤时间，不回答学区划分或就学资格。
- 可以按用户明确需求说明字段匹配情况；不把“优质”“值得买”等主观判断当作数据结论，不承诺涨价或投资收益。
- 所问核心信息不足时，不调用本节点，系统转 JLIMIT 固定受限说明。只有其他相关资料不足时，保留已知说明并标出待核实项。
- 输出进入 JCHECK 核验，失败转 JREJECT/JLIMIT；通过后才可展示。

## 失败处理

AI 超时或无效结构走 JE2，保留原问题。模型引用不存在字段、错误项目或不匹配数字时，不展示生成内容，转受限说明和真实业务入口。

## 验收

- 只问价格但无有效价格字段 → JLIMIT，不编造数值。
- 有户型、面积，无价格，用户问户型 → 可说明户型，价格标为未核实。
- 问“会不会涨价” → 不承诺涨幅、回报或投资收益。
- 返回的项目 ID 与已选项目不同 → 系统拦截。

## 可复用提示词与依据

仅根据本轮已验证项目字段回答当前问题。逐项保留数字、单位、价格口径和来源；缺少信息明确说明，禁止从常识、历史印象或其他项目补写。输出结构化解读供系统校验。
