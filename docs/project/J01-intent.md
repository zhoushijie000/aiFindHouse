# J01 · 楼盘解读意图识别

> 本文为新增楼盘解读流程的建议输出契约，复用 H01 的四类意图定义；JSON 为示意，不代表真实项目数据。

## 职责与触发

收到用户消息或楼盘卡片的解读操作后，结合有效上下文判断业务目标。咨询某个具体楼盘为 `PROJECT_QUERY`；寻找其他类似楼盘为 `FIND_HOUSE`；查政策与解读政策分别为 `POLICY_QUERY`、`POLICY_INTERPRET`。完整定义见 [共用意图识别 Prompt](../house/H01-intent.md)。

## 输入

- 用户当前问题、必要历史对话、已选择楼盘及上轮待确认对象。
- 当前支持的四类意图，不由模型添加新的业务类型。

## AI 输出 JSON 示例

用户在已选定楼盘后问“它有哪些户型？”：

```json
{
  "node_id": "J01",
  "intent": "PROJECT_QUERY",
  "multi_intent": false,
  "need_clarification": false,
  "next_node": "J02"
}
```

## 字段与路由

- `intent`：四类枚举之一或 `null`；`null` 不是第五种意图。
- `multi_intent`：多个独立目标按共用 Prompt 输出主、次意图，由系统安排路由，不静默丢弃。
- `need_clarification`：是否缺少判断业务意图的信息；不是缺少项目字段。
- `next_node`：本流程为 J02；其他已识别业务转对应流程；意图为 `null` 时转 JG。

## 系统固定引导

结合上下文仍未识别到意图时，由系统 JG 原样返回以下文案，AI 不生成或改写：

> 安安是你的购房小助手，我可以帮你找成都新房，以及查询成都购房支持政策。你可以告诉我想买哪个区域、预算多少，或者想了解哪类购房支持政策。

返回后等待用户继续提问，不调用业务查询。“解读一个楼盘”已能判断为楼盘解读，只是未指定对象，应进入 J02/J03，不能当作未识别意图。

## 约束与失败处理

- 本节点不回答项目事实，不查询业务数据，不创造项目 ID。
- 短句继承有效对象；明确改问其他业务时切换路由。
- AI 超时或结构错误进入 AI 异常重试，不按意图未命中处理。

## 验收

- “某楼盘怎么样” → PROJECT_QUERY。
- “找几个和它类似的楼盘” → FIND_HOUSE。
- “这个怎么样”且无有效上下文 → intent 为 null，系统固定引导。

## 依据

用户补充的 H01 楼盘意图定义、本次新增楼盘解读要求、需求原文 §2.4.1、§2.4.6—2.4.7。
