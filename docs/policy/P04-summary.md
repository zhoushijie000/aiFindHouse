# P04 · 政策结果概括

> 本文为**建议输出契约**，字段及示例不是原文 API。所有示意政策均不是真实政策，日期仅用于验证界面和时效判定。

## 节点职责

在真实政策库查询成功且有结果后，生成简短概括并引用政策卡片。AI 组织文本；真实条目、卡片字段、排序、有效状态和详情路径由业务系统提供并校验。

## 触发

政策查询成功且返回至少一条已验证政策；系统已完成排序、有效期判定与数量截断。

## 输入

- `query_filters`：实际执行的查询条件。
- `total_count` 与 `displayed_policies`：实际命中数及本次最多 5 条。
- 每条政策的真实 ID、名称、标签、有效期、正文是否可用及官方详情路径。
- `computed_status`：系统根据服务端当前日期判定的已生效、即将生效、已失效或未知。
- `sort_basis`：系统实际使用的发布时间或生效时间排序口径。

## AI 输出 JSON 示例

```json
{
  "node_id": "P04",
  "reply": "查询到 2 条示意政策。其中 1 条已生效，1 条即将生效。当前数据仅提供标题和有效期，具体补贴标准和申请条件需要进入政策详情查看。",
  "policy_refs": [
    {"policy_id": "demo-policy-a", "status": "active"},
    {"policy_id": "demo-policy-b", "status": "upcoming"}
  ],
  "display_count": 2,
  "body_summary_available": false,
  "next_node": "PD3"
}
```

示意输入：系统日期为 `2026-09-17`（Asia/Shanghai）；示意 A 的有效期为 `2026-01-01—2026-12-31`，示意 B 为 `2026-10-01—2026-12-31`。状态由系统计算，AI 仅引用。

## 字段说明

| 字段 | 说明 |
| --- | --- |
| `reply` | 简短概括，普通回答建议 50—150 字。 |
| `policy_refs` | 本次结果中的政策 ID 与系统状态引用，不能新增条目。 |
| `status` | `active` 已生效、`upcoming` 即将生效、`expired` 已失效、`unknown` 无法判定。 |
| `display_count` | 本次展示条数，最多 5 条，不等同于全部命中数量。 |
| `body_summary_available` | 是否有完整可引用正文支持内容概括。 |

## 约束

1. 单次最多展示 5 条政策；卡片展示政策名称、标签、有效期和查看详情入口。不能因为 AI 概括长度改变真实数量。
2. “最新”按系统选择的发布时间或生效时间倒序。排序口径应统一；原文未确定二选一的具体优先级，需实现时明确。
3. 起始日期晚于系统当前日期必须标记“即将生效”，不得写为“当前正在执行”。已失效政策不能被介绍为当前政策。
4. 状态由系统时区与日期精度规则计算，AI 不使用自身记忆日期。缺少有效期或日期相互矛盾时标记“有效状态待核实”，不能猜测。
5. 只有标题和有效期时，仅说明查到哪些条目及可核验的时间信息，不推断补贴金额、适用对象、申请条件或覆盖范围。
6. 有正文时可忠实概括已查得内容，不作个体资格、补贴承诺或学区归属判断。对“不得回答具体政策结论”与“可简单总结”采用此保守解释。
7. 详情路径取自系统校验的真实路由，不由 AI 自行拼接未经定义的 URL。

## 失败处理

- 查询成功且零条：进入 P06，不调用本节点生成“查到政策”。
- 政策接口异常：提示“政策数据暂时没有查询成功，请稍后重试。”，不能视为零结果。
- AI 异常：可由系统展示已验证卡片与固定说明，或标准 AI 异常提示；不能补造概括。
- 发现非结果内 ID、超 5 条或日期矛盾：系统拒绝无效输出并使用可核验卡片兜底。

## 验收样例

| 场景 | 预期 |
| --- | --- |
| 命中 12 条 | 展示最多 5 条，不写“总共只有 5 条”。 |
| 发布时间最新，但生效日期晚于系统日期 | 显示“即将生效”。 |
| 标题包含“补贴”，但没有正文 | 不补写额度、条件，仅引导详情。 |
| 没有结束日期且无法确认有效状态 | 标记待核实，不擅自认定长期有效。 |
