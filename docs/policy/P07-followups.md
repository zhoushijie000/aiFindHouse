# P07 · 政策下一步推荐问题

> 本文为**建议输出契约**。示例政策与路径引用仅用于演示；普通结果后的追问数量建议最多 3 个，原文明确“最多 3 个”的位置是零结果推荐，此处采用统一体验的补充建议。

## 节点职责

在政策结果或解读输出后，生成与真实结果及数据可用性一致的下一步候选问题或操作入口。所有候选交后续系统 PV 按操作类型核验结果、正文与路径，通过后才展示。让用户继续查询或查看原文，不能诱导用户点进系统无法回答的虚构解读。

## 触发

P04 已输出真实查询结果，或 P05 已完成正文解读，或系统 PN 已输出固定受限说明；零结果场景推荐由 P06 处理。

## 输入

- `current_filters`：当前政策筛选条件。
- `displayed_policies`：已展示政策及真实 ID。
- `body_availability_by_policy`：每条政策的正文可用状态。
- `available_routes`：业务输入中已存在的详情或原文入口及其引用，可供候选引用，后续由 PV 核验当前可用性。
- `available_policy_facets`：真实政策库的区域、类型等覆盖线索，用于提出新查询候选；不等同于候选查询已经验证有结果。
- `recent_questions`：减少重复追问。

## AI 输出 JSON 示例

```json
{
  "node_id": "P07",
  "suggestions": [
    {
      "label": "查看示意政策 A 的详情",
      "action": "open_policy_detail",
      "policy_id": "demo-policy-a",
      "route_ref": "demo-route-a",
      "question": null,
      "requires_body": false,
      "verification_state": "pending_system_query"
    }
  ],
  "generation_reason": "当前条目没有可供解读的正文，仅提出引用已有详情入口的待验证候选",
  "next_node": "PV"
}
```

示例假定业务输入确认政策 A 存在并提供详情路径，但无政策正文。实际候选必须引用真实业务数据，并等待后续系统 PV 核验；本次 JSON 输出不能直接展示为推荐入口。

## 字段说明

| 字段 | 说明 |
| --- | --- |
| `suggestions` | 待验证候选，建议最多 3 项，可少于 3 项或为空；PV 通过前隐藏。 |
| `label` | 用户可见的简短问题或操作文案。 |
| `action` | `ask_policy_question` 发送政策追问、`run_policy_query` 再次查询、`open_policy_detail` 打开详情。 |
| `policy_id` | 来源于真实结果的政策 ID。 |
| `route_ref` | 引用业务输入中已有详情或原文路径，不是 AI 自造链接；PV 展示前核验其可用性。 |
| `proposed_query` | 新查询候选的结构化条件，按业务字典提出；由后续 PV 实际查询验证并产生真实查询引用，不要求前置已验证的 `query_ref`。 |
| `question` | 需要发送的完整问题；直接跳详情时为空。 |
| `requires_body` | 解读类问题为 `true`，系统须确认相应正文可用。 |
| `verification_state` | 本节点固定 `pending_system_query`；后续 PV 按操作类型核验结果、正文与路径，AI 不自证通过。 |
| `generation_reason` | 便于调试的简要选择依据，通常不展示给终端用户。 |

## 约束

1. 有正文时，可提出“这项政策的申请条件是什么”等正文确实能够回答的问题；问题涉及的条件必须在已获取正文中存在。
2. 无正文时，不推荐“我能领多少钱”“帮我判断资格”“解读补贴条件”等会暗示 AI 已掌握正文的入口。可提供查看详情或有真实数据支撑的政策查询。
3. 即使有正文，也不推荐以“确认我能领到补贴”为目标的操作；本流程不包含个体资格判定引擎。
4. 其他区域或政策类型的候选必须依据真实库覆盖线索提出，不能虚构政策。新查询候选在本节点输出时尚未验证，后续 PV 必须实际查询并确认有结果才允许展示。
5. 已失效政策的后续问题必须明确历史属性；不得把未来生效政策描述为正在执行。
6. 点击问题回到 P01/P02，并保留政策上下文；点击详情按 2.4.4 保存会话，1 天内返回恢复原对话、卡片、追问、条件与滚动位置。
7. 管理端开场随机 3 个引导问题与本节点的结果后推荐不是同一数据来源；不能把运营通用问题冒充已检索结果。
8. 所有候选先进入 PV：查询类核验实际结果数，解读类核验对应完整正文及问题依据，详情类核验真实政策与入口可用性。通过后直接展示候选文案，无需第二次 AI 调用；失败候选隐藏，原政策结果保持可见。

## 失败处理

- 无可支持的下一步问题：返回空数组，保留用户自由输入，不凑数。
- 详情入口失效：隐藏该操作或提示详情暂不可用，不生成假链接。
- 正文未就绪：隐藏需要正文的解读问题，改用有效详情入口。
- 推荐生成失败：保留已经成功的政策结果，不清空整轮回复。

## 验收样例

| 场景 | 预期 |
| --- | --- |
| 只有标题、有效期和详情链接 | 可推荐查看详情，不推荐额度解读。 |
| 正文未提申请材料 | 不推荐“准备哪些材料”作为可直接回答的问题。 |
| 有真实库覆盖线索，提出改查邻区但尚未执行验证 | 输出 pending 候选并交 PV，验证通过前隐藏。 |
| 引用了已有详情入口 | 仍交 PV 核验当前路径可用性，通过后展示。 |
| 用户打开详情并在 1 天内返回 | 恢复会话位置、结果和推荐追问。 |

## 可复用提示词

根据已查询政策、真实库覆盖线索及正文可用性提出少量下一步候选。所有问题须有真实数据依据，所有路由须来自业务输入；新查询输出待验证条件。候选统一标记 pending_system_query，交后续 PV 核验结果、正文及路径后决定能否展示。无正文不邀请虚构解读，不承诺个体资格；没有可支持建议则输出空数组。
