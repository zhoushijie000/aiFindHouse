# H07 · 下一步推荐问题

> 本文为建议的 AI 输出契约，字段名并非原需求文档已有 API。JSON 为示意；本节点最多 3 个及“验证后展示”为沿用零结果规则的一致性设计建议，原文未单独给出有结果追问的数量与验证规则。

## 节点职责与触发

本轮已有楼盘结果并完成 H05 后，依据用户条件与真实结果提出下一步可执行问题。优先细化需求或查看结果相关信息，让用户继续查询；所有展示候选均由系统验证。

## 输入

- 当前意图、已确认筛选条件与其中的硬性条件。
- 本轮真实结果、可用字段与支持的查询动作。
- 系统保存的当前上下文；本节点生成待验证候选，不依赖后续系统验证的结果。

## AI 输出 JSON 示例

示意输入：当前为青羊区、400 万元以内，本轮返回数据中具有三室字段。

```json
{
  "node_id": "H07",
  "query_ref": "demo_query_01",
  "candidate_questions": [
    {
      "candidate_id": "demo_followup_01",
      "question": "这些项目中有哪些三室户型？",
      "intent": "new_home_search",
      "preserve_conditions": {
        "region_name": "青羊区",
        "total_price_wan": { "operator": "lte", "value": 400 }
      },
      "additional_conditions": { "bedroom_count": 3 },
      "verification_state": "pending_system_query"
    }
  ]
}
```

## 字段说明

| 字段 | 含义 |
| --- | --- |
| `query_ref` | 推荐问题基于的本轮结果引用 |
| `question` | 用户可点击的完整问题，须和实际执行条件一致 |
| `preserve_conditions` | 沿用原始硬性条件，不能隐藏修改 |
| `additional_conditions` | 用户选择后追加的条件或系统允许的细化动作 |
| `verification_state` | AI 仅返回待验证；系统执行真实查询决定能否展示 |

## 输出约束与系统衔接

- 系统验证候选查询仍保留原区域、预算等硬性条件，并确认有可展示业务数据；通过后才展示，建议最多 3 个。
- AI 不得把“400万以内”改成“500万以内”或换区域来凑足推荐；需要更改时必须作为明确变更建议，经用户选择后执行。
- 问题必须能通过现有能力回答，不能推荐无地图能力的通勤时间问题或需要模型臆测的学区问题。
- 追问候选不是管理端配置的欢迎问题。首次默认随机 3 个的问题由管理端配置返回，无需本节点重新生成。
- 点击候选相当于发送新问题，继续 H01/H02 并继承上下文；执行时再次查询最新数据。
- 离开 AI 去详情页时，问题、回答、卡片、推荐追问、筛选条件和滚动位置由系统保存；1 天内返回恢复，不由 AI 重建。

## 失败处理

没有验证通过的候选时隐藏推荐区，保留本轮正常答案及输入框；推荐失败不能覆盖已成功的查询结果。AI 或验证接口失败时不填充未经验证的问题。

## 验收样例

| 场景 | 预期 |
| --- | --- |
| 青羊区400万以内，推荐三室 | 验证条件包含原区域和预算 |
| AI 建议500万以内但未明示预算变更 | 拒绝该候选 |
| 只有2个候选验证通过 | 只展示2个，不补造 |
| 返回详情后1天内回AI | 恢复原推荐及会话，不重新欢迎 |
