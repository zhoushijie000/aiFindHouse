# H05 · 有结果时组织简短说明

> 本文为建议的 AI 输出契约，字段名并非原需求文档已有 API。项目标识与数量仅用于说明数据结构，不代表真实楼盘。

## 节点职责与触发

楼盘业务接口成功且有匹配数据后，AI 基于系统提供的结果生成简短说明，并引用本轮真实返回的项目。前端业务卡片及可用跳转路径由系统数据生成。

## 输入

- 用户已确认条件、系统执行的查询条件及查询标识。
- 查询成功标志、匹配总数、系统筛选排序后的最多 5 个项目。
- 项目真实字段、价格口径、数据时间及可用的业务详情/联系路径。

## AI 输出 JSON 示例

示意输入：演示接口返回 3 个项目，价格字段明确为项目起步总价。

```json
{
  "node_id": "H05",
  "query_ref": "demo_query_01",
  "summary": "本次查询找到3个符合条件的在售项目，已为你展示。下方价格为项目起步总价，具体可进入楼盘详情查看；你也可以继续补充面积或户型需求。",
  "display_project_refs": ["demo_project_01", "demo_project_02", "demo_project_03"],
  "claims": [
    { "kind": "match_count", "source_field": "query.matched_total" },
    { "kind": "price_basis", "source_field": "query.price_basis" }
  ]
}
```

## 字段说明

| 字段 | 含义 |
| --- | --- |
| `query_ref` | 系统本轮查询引用，避免混用历史结果 |
| `summary` | 用户可见说明，通常 50～150 字，不重复展开全部卡片字段 |
| `display_project_refs` | 仅引用本轮候选项目，最多 5 个；不可新增 ID |
| `claims` | 可核验陈述的业务来源，用于系统校验 |

## 输出约束

- 是否存在、在售状态、价格、面积、户型、标签、剩余房源一律来自实时业务结果；字段缺失就不解释该字段。
- 总匹配数与本次展示数区分：匹配 18 个、展示 5 个时不能写“只找到5个”。
- 优先满足硬性条件，排序可参考预算、区域、产品需求、面积户型、可售情况；不能用运营推广顺序替代自然推荐。
- 详情和在线联系路径必须是系统按真实业务标识解析的有效路由；模型不拼接路径。原文的“AI返回路径”在实现上由系统组装最终响应完成。
- 联系能力或顾问路径不可用时不展示失效入口；原文允许置业顾问能力后置。
- 不承诺升值、投资收益或学区资格。只有接口明确价格口径时才可写“起步总价”。

## 失败处理

项目引用或说明事实无法校验时，重新生成或采用系统模板。楼盘接口失败展示“楼盘数据暂时没有查询成功，请稍后重试。”；不能进入零结果分支。AI 服务失败使用 AI 异常提示。

## 验收样例

| 输入 | 预期 |
| --- | --- |
| 接口返回8个候选 | 单次展示最多5个，文案区分总数与展示数 |
| 项目价格字段为空 | 不编造价格或价格范围 |
| 模型引用未返回的项目 ID | 系统拒绝该引用 |
| 楼盘接口超时 | 异常提示，不写“暂无楼盘” |

## 可复用提示词

只解释提供的本轮查询结果，逐项保持事实可追溯。简短说明匹配情况，仅引用已有项目，不生成项目字段、价格或跳转路径。
