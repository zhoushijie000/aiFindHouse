# H02 · 条件提取与上下文合并

> 本文为建议的 AI 输出契约，字段名并非原需求文档已有 API。所有 JSON 值均为示意。

## 节点职责与触发

意图为找新房时，提取本轮新增、替换或清除的条件，合并到已确认上下文；保留原始表达、比较符、确定程度与硬性条件。

## 输入

- 用户原文、当前已确认条件、上轮待回答的追问。
- 系统允许查询的字段与枚举、单位规范、默认解释规则。

## AI 输出 JSON 示例

示意输入：已确认“青羊区、300万元以内”，本轮“预算提高到400万呢？”

```json
{
  "node_id": "H02",
  "updates": [
    {
      "field": "total_price_wan",
      "operation": "replace",
      "raw_text": "预算提高到400万",
      "operator": "lte",
      "value": 400,
      "certainty": "context_inferred",
      "hard_constraint": true
    }
  ],
  "merged_conditions": {
    "region_name": "青羊区",
    "total_price_wan": { "operator": "lte", "value": 400 }
  },
  "unresolved": [],
  "nonstandard_needs": []
}
```

## 字段说明

| 字段 | 含义 |
| --- | --- |
| `updates` | 本轮变更；操作为 add / replace / clear |
| `operator` | lte（以内）、gte（以上）、between（区间）、around（左右）；不可混用 |
| `certainty` | explicit（明确）、context_inferred（上下文推断）、ambiguous（待确认） |
| `hard_constraint` | 是否属于必须保留的用户条件；映射偏好不自动升级为硬条件 |
| `merged_conditions` | 合并后的候选查询条件，由系统校验后保存 |
| `unresolved` | 缺失单位、口径冲突、近似范围等待确认项 |
| `nonstandard_needs` | “改善”“通勤方便”等待 H03 转换的需求及原文 |

## 输出约束

- 总价与首付分开，万元与平方米分开；未给贷款条件时不能把首付反推为总价。
- “300万以内”为上限，“3000万以上”为下限；“300万左右”保留 around，容差需业务规则或用户确认，不擅自生成区间。
- 原文“青羊区300万新房”按上限示例处理，但记录为业务约定解释；不声称是用户明确说了“以内”。
- “换成锦江区”只替换区域，“预算提高”只替换预算；“不限预算”才清除对应预算条件。
- 区域名、项目名交由业务字典消歧及 ID 解析；AI 不生成真实项目 ID。
- 含糊或互相矛盾的条件进入 H04，不把低确定性猜测直接当硬性筛选。

## 失败处理

字段、比较符或单位校验失败时保留上次确认条件，修复或追问；不得用非法条件查询。AI 故障统一使用原文异常提示。

## 验收样例

| 输入/上下文 | 预期 |
| --- | --- |
| 青羊区3000万以上 | gte 3000，不能变为上限 |
| 300万左右 | 标记 around；没有容差规则时待确认 |
| 上轮青羊区400万以内；“换成锦江区” | 保留预算，仅改区域 |
| 首付80万 | 记录首付，不能等同总价80万 |

## 可复用提示词

只提取用户表达和可追溯的上下文，不补造预算、面积或楼盘 ID。逐字段说明本轮变更，保留比较符及不确定项。
