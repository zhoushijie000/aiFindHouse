# H03 · 非标准需求转换

> 本文为建议的 AI 输出契约，字段名并非原需求文档已有 API。JSON 与价格分位值均为示意，不代表成都实时行情。

## 节点职责与触发

H02 出现“改善”“低密”“通勤方便”等非标准需求时，结合系统字段能力、知识库映射和业务统计，把可支持的语义转成候选筛选条件。需要统计或地图数据时先请求系统取数，再执行转换。

## 输入

- 原始语义需求、已确认区域及预算等条件。
- 系统字段能力和配置过的语义映射规则。
- 系统查询得到的区域价格分布及查询标识；地图能力、点位和路线结果（如具备）。

## AI 输出 JSON 示例

示意场景：系统已查询某区域价格分布，业务映射配置规定以 P50～P90 作为“改善”的候选价格参考。

```json
{
  "node_id": "H03",
  "status": "mapping_proposed",
  "source_need": "改善",
  "evidence_refs": ["demo_price_distribution_01", "demo_mapping_rule_01"],
  "proposed_filters": [
    {
      "field": "total_price_wan",
      "operator": "between",
      "min": 390,
      "max": 900,
      "source": "system_distribution_and_rule",
      "hard_constraint": false
    }
  ],
  "explanation": "可先参考系统返回的区域价格分布筛选改善方向；价格只是筛选参考。",
  "required_data": [],
  "unavailable_capabilities": []
}
```

## 字段说明

| 字段 | 含义 |
| --- | --- |
| `status` | need_system_data / mapping_proposed / need_clarification / unsupported |
| `source_need` | 用户非标准需求原文 |
| `evidence_refs` | 系统实际传入的统计或规则引用，不由 AI 创造 |
| `proposed_filters` | 建议映射条件；必须通过系统字段及原硬条件校验 |
| `required_data` | 所需数据类型和限定范围，由系统执行查询 |
| `unavailable_capabilities` | 当前不可用能力，用于透明说明与追问 |

## 输出约束

- 原文的 P50/P70/P90 与 450～800 万只是流程示例，没有确定映射算法；不能硬编码为真实市场规则。示例中的 P50～P90 也是建议配置，仅用于解释契约。
- 没有区域价格统计时先返回 need_system_data；不能凭自身知识生成分位值或项目价格。
- 新映射不能覆盖用户明确的预算上限。若与硬性条件冲突，应保留硬条件并说明或追问。
- 开发商、低密、地铁等仅使用业务字段或有依据的知识库映射；不推断不存在的标签。
- 通勤筛选需要地图服务、点位及路线数据；没有能力则说明暂不能计算通勤距离/时间，可请用户选择区域或提供期望片区。不得编造“30分钟可达”。

## 失败处理

统计或地图接口失败属于取数异常，不能伪装为“没有符合的楼盘”。允许返回明确已支持条件继续查询的建议，必须由用户选择或符合已约定的流程规则。

## 验收样例

| 输入/能力 | 预期 |
| --- | --- |
| 高新区改善；无分布数据 | 请求区域价格统计，不能直接给价格区间 |
| 改善；明确预算300万以内 | 映射不覆盖预算上限 |
| 骡马市通勤30分钟；无地图服务 | 说明不可计算并追问可用筛选项 |
| 低密；系统无字段且无知识映射 | 保留需求，说明未支持，不能伪造匹配 |
