# H04 · 信息充分性判断与条件补充追问

> 本文为建议的 AI 输出契约，字段名并非原需求文档已有 API。JSON 均为示意；最小查询范围的具体规则需由业务接口能力配置。

## 节点职责与触发

条件提取和非标准需求处理后，检查是否能形成系统支持、边界清楚的最小查询范围。只追问阻碍当前查询的条件，不要求用户一次填全所有字段。

## 输入

- 合并后的条件、待确认项、已解析的具体楼盘、已知语义转换结果。
- 系统最小查询范围规则、可支持的全市或单区查询能力。
- 当前会话中已经问过的问题。

## AI 输出 JSON 示例

示意输入：“帮我找房”，当前没有任何有效筛选条件。

```json
{
  "node_id": "H04",
  "query_ready": false,
  "blocking_items": ["query_scope"],
  "question": "可以，你想在哪个区县找房？购房总预算大概多少？例如：青羊区，400万以内。",
  "requested_fields": ["region", "total_price"],
  "preserved_conditions": {},
  "next_route": "wait_for_user"
}
```

## 字段说明

| 字段 | 含义 |
| --- | --- |
| `query_ready` | 候选条件可查询；最终由系统规则判断 |
| `blocking_items` | 当前阻止查询的条件或歧义；空数组表示没有阻碍 |
| `question` | 简短、可回答的补充问题；可查询时为空 |
| `requested_fields` | 本轮建议补充字段，不等于全部必填字段 |
| `preserved_conditions` | 已确认条件，保证用户补充后继续沿用 |
| `next_route` | 等待用户或进入业务楼盘查询 |

## 输出约束

- 原文未给出统一最小范围算法，不能一刀切地把区域、预算、面积、户型全部设为必填。
- 用户只提供具体楼盘，且系统已唯一解析为项目，即可查询该楼盘；不能强制补预算。
- 仅提供区域是否可查，按系统范围与数量限制规则决定；若可查，不能无故拦截。原文逐轮补充预算是对话示例，不等于全局硬性校验。
- “左右”的范围、同名楼盘或条件冲突等关键歧义应先澄清；不重复询问已经确定的字段。
- 追问只生成文本和建议字段，不能生成查询成功结果或项目卡片。

## 失败处理

系统规则与 AI 判断不一致时采用系统规则；保留已有条件再追问。模型失败时返回 AI 异常提示并允许重试，不清空会话。

## 验收样例

| 输入/系统能力 | 预期 |
| --- | --- |
| 帮我找房；没有有效条件 | 补充区域或预算等最小范围 |
| 示例楼盘甲；已唯一解析 | 可直接查询该项目 |
| 只有青羊区；单区查询可用 | 可查询，不强制填满字段 |
| 上轮区域已确定；本轮400万 | 合并预算并判断可查，不再问区域 |

## 可复用提示词

根据传入的系统规则判断是否可查，只追问阻碍查询的信息。具体楼盘已唯一解析时允许直接查询；不要将示例对话误设为全局必填表单。
