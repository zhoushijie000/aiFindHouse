### 2.4 AI

![image.png](https://alidocs.oss-cn-zhangjiakou.aliyuncs.com/res/ybEnB5NwArWxBlP1/img/b3a4965e-7b99-4741-9ff1-ff3948dc87d1.png)

*   开场语：管理端配置返回
    

*   用户引导：管理端按照新房、政策、 二手房配置推荐问题（默认随机展示3个），引导用户提问方式。
    

#### 2.4.1 ai整体处理流程:

用户发送问题后，系统按照以下流程处理：

**用户问题 → 意图识别 → 条件提取（最小查询范围） → 判断信息是否充分 → 查询业务数据 → AI组织答案 → 返回业务卡片 → 生成下一步推荐问题**

AI首先判断用户属于哪一种业务意图：

**A. 找房意图**

例如：

“青羊区300万有什么新房？”

“高新区改善楼盘有哪些？”

“我在骡马市上班，想买通勤方便的房子。”

**B. 购房支持政策查询意图**

例如：

“青羊区有什么购房支持政策？”

“成都哪些区域有人才购房补贴？”

“最近有什么新的购房政策？”

**C. 无法识别（引导服务范围内）**

如果用户输入内容与找房、购房支持政策均无明显关系，则不进行开放式自由回答。

引导：

“安安是你的购房小助手，当前问题已经超出了我的能力范围，目前我主要可以帮你找成都新房，以及查询成都购房支持政策。你可以告诉我想买哪个区域、预算多少，或者想了解哪类购房支持政策。”

#### 2.4.2 找新房

用户的问题包含以下信息时，可优先识别为找房需求：

区域、楼盘、预算（总价、首付款）、面积、户型、位置等。

例如：

“青羊区300万新房”

应识别为：

```text
意图：找新房
区域：青羊区
预算上限：300万元
```

“高新区有哪些改善型楼盘”（知识库）

当用户提出系统不存在的字段时，由大模型加工转化为系统存在的条件

```text
用户：
“我想买高新区改善楼盘”

        ↓

① 大模型理解
{
  区域：高新区
  需求：改善
}

        ↓

② 系统能力判断

改善字段：不存在
价格字段：存在

        ↓

③ 查询区域价格分布

P50：390万
P70：520万
P90：900万

        ↓

④ 大模型二次转换

改善
→ 查询 450～800万

        ↓

⑤ 楼盘数据库查询

        ↓

⑥ 返回楼盘

        ↓

⑦ AI生成解释
```

“青羊区3000万以上的楼盘”

识别为：

```text
意图：找新房
区域：青羊区
预算下限：3000万元
```

需要区分，如：

300万以内；

300万左右；

300万以上。

避免统一按照“300万”处理。

*   **条件体系**
    

| 条件 | 示例 | 备注 |
| --- | --- | --- |
| 行政区域 | 青羊区、高新区、锦江区 |  |
| 板块 | 大面、金融城等 |  |
| 预算 | 300万、400万以内、3000万以上 |  |
| 具体楼盘 | 招商时代花园 |  |
| 楼盘位置 | 骡马市、金融城、天府广场 | 1、通勤场景可能无法实现（需要地图mcp、点位数据） |
| 面积需求 | 120㎡左右、140㎡以上 |  |
| 户型 | 三室、五室 |  |
| 开发商 | 龙湖、保利 | 需要llm加工 |
| 其他关键词 | 地铁、低密、小高层等 | 需要llm加工（知识库） |

*   **条件补充**
    

用户不需要一次性提供所有条件。

AI应支持逐步补充需求。

例如用户输入：

“帮我找房。”

AI回答：

“可以，你想在哪个区县找房？购房总预算大概多少？例如：青羊区，400万以内。”

用户继续输入：

“青羊区。”

AI应继承上一轮“找房”意图，而不是重新理解为一个独立问题。

AI可继续询问：

“好的，青羊区。你的购房总预算大概是多少？”

用户：

“400万。”

最终形成：

```text
区域：青羊区
预算：400万元以内
```

并自动查询楼盘。

*   **上下问能力**
    

AI必须具备基础会话上下文能力。

例如：

用户：

“青羊区300万有哪些新房？”

AI返回结果。

用户：

“预算提高到400万呢？”

系统应理解为：

```text
原区域：青羊区
原预算：300万
新预算：400万

```

最终查询：

**青羊区 + 400万预算**

而不能将“预算提高到400万呢”作为一个完全独立的问题处理。

同理：

“换成锦江区呢？”

应仅修改区域条件，其余条件继续沿用。

*   **楼盘查询逻辑（最小查询范围）**
    

AI完成用户需求理解后，不允许直接根据大模型自身知识推荐楼盘。

必须调用房产超市楼盘数据库进行查询。

整体流程：

**AI提取条件 → 楼盘查询接口 → 返回符合条件楼盘 → AI生成说明 → 前端展示楼盘卡片**

其中：

楼盘是否存在；

楼盘是否在售；

所在区域；

总价；

面积；

户型；

标签；

剩余房源等信息，

均应以房产超市实时业务数据为准。

AI只负责：

**理解用户需求 + 解释查询结果。**

不得自行创造楼盘。

*   **找房结果展示**
    

存在符合条件的楼盘时，AI首先返回一段简短说明：

例如：

“根据你的需求，目前找到3个符合条件的在售项目。以下价格为项目起步总价，具体请进入楼盘详情查看。”

ai返回楼盘页面路径和置业顾问沟通路径（置业顾问可以后置）：

如：projectId=1948618865965535234

下方展示楼盘卡片。

点击楼盘卡片：

进入对应楼盘详情。

点击“在线联系”：

进入该项目置业顾问在线沟通页面。

AI回答不需要把所有楼盘字段转换成长篇文字，核心信息前端通过卡片展示。

*   **AI推荐数量限制**
    

单次建议最多返回5个项目：

当项目数量较多时，应优先展示与用户条件匹配度较高的项目。

建议排序优先级：

1.  完全满足用户硬性条件；
    
2.  预算匹配度；
    
3.  区域匹配；
    
4.  产品需求匹配；
    
5.  面积/户型匹配；
    
6.  在售及可售房源情况。
    

不得单纯根据运营推广顺序改变AI自然推荐结果。

如未来存在商业推广项目，应单独标识推广属性。

*   **零结果引导（推荐楼盘接口）**
    

AI查询不到符合条件的楼盘时，不直接返回：

“暂无结果。”

而应继续帮助用户调整条件。

例如用户：

“青羊区有没有5000万左右的楼盘？”

如果无匹配结果：

“暂未找到完全符合条件的在售新房。青羊区目前这一总价段可选项目较少，我可以保留你的高端改善需求，换个条件继续找。”

下方展示：

**你可以试着问问**

例如：

“青羊区3000万以上有哪些楼盘？”

“锦江区5000万级有哪些楼盘？”

“成都5000万级豪宅有哪些？”

点击后直接再次查询。

*   **零结果推荐问题生成逻辑**
    

推荐问题不能由AI随意编造。

应按照用户原始需求生成，并通过实际数据查询确认该问题存在结果后再展示。

推荐优先级：

方案1：保留区域，调整预算

青羊区5000万→ 青羊区3000万以上

方案2：保留预算，调整区域

青羊区5000万→ 锦江区5000万

方案3：保留购房档次，扩大区域

青羊区5000万→ 成都5000万级楼盘

方案4：放宽全部限制

→ 不限区域和预算，看看现有楼盘

最终最多推荐3个问题。

原则：

推荐的问题必须能够查询到数据。

否则用户连续点击后仍然零结果，会严重降低AI可信度。

#### 2.4.3 购房支持政策查询

*   **意图识别条件**
    

用户输入包含：

政策；

购房政策；

补贴；

人才；

消费券；

以旧换新；

房票；

教育/就学；

车位等相关内容时，

识别为：

\*\*购房支持政策查询。

*   **查询条件**
    

AI需要从用户问题中识别：

**区域：**

青羊区；

锦江区；

成华区；

成都全市。

**政策类型：**

包括但不限于：

人才购房支持；

购房补贴；

购房消费券；

以旧换新；

房票购房；

交通优惠；

车位购买支持；

就学支持等。

**时间要求：**

例如：

“现在有什么政策？”

“最新政策是什么？”

“最近有哪些购房补贴？”

识别用户存在“当前/最新”要求。

*   **查询结果**
    

存在匹配政策时，AI先进行简短概括。

例如：

“从当前政策信息看，青羊区目前主要包含人才购房支持、购房补贴及相关消费支持。建议重点关注适用对象、申请条件和政策有效期。”

返回政策页面路径。

如“id=2033388986398879745”

随后展示政策卡片

单次最多展示：

**5条政策。**

政策卡片包含：

*   政策名称；
    
*   政策标签；
    
*   有效期；
    
*   查看政策详情。
    

点击：

**查看政策详情**

进入政策详情页面。

*   **最新政策处理**
    

当用户提出：

“最新购房支持政策”

系统按照政策发布时间或生效时间倒序展示。

但需要区分：

已生效；

尚未生效；

已失效。

如果起始日期晚于当前时间，应明确标识：

**即将生效**

不能因为发布时间较新，就直接回答为“当前正在执行”。

*   **政策解读**
    

如：

“请解读青羊区人才补贴”

AI可以对政策查询结果进行简单总结，但不得修改政策原意。

AI回答建议采用：

**结论 + 注意事项 + 政策原文入口**

例如：

“目前查询到青羊区有3项相关购房支持政策，其中部分政策对人才类别、购买区域或申请时间存在要求。是否能够享受支持，需要结合具体政策中的适用对象和申请条件判断。”

避免：

“你肯定可以领取10万元补贴。”

除非用户条件已经完整，并且规则能够通过结构化数据准确判断。

*   **政策零结果展示**
    

当用户查询的政策类型暂不存在时：

“当前政策数据中暂未找到与你的查询相匹配的政策，可以换一个支持方向或区域继续了解。”

同时根据政策库真实数据推荐最多3个可查询问题。

例如：

**你可以问问**

“高新区有哪些人才购房支持政策？”

“青羊区有哪些购房补贴政策？”

“成都哪些区域有购房消费券？”

*   **政策准确性要求**
    

政策场景属于高准确性业务。

AI必须遵循：

**不回答具体政策结论。**

如果平台政策库中只有政策标题和有效期，没有政策正文，则只能说明：

“当前可以查询到该政策，但具体补贴标准和申请条件需要进入政策详情查看。”

不得由AI自行补全。

#### 2.4.4 对话历史保持

用户在AI中完成查询后，如果点击：

楼盘详情；

政策详情；

其他业务页面，

系统应保存当前AI会话状态。

保存内容至少包括：

*   用户历史问题；
    
*   AI历史回答；
    
*   楼盘/政策卡片；
    
*   推荐追问；
    
*   当前找房筛选条件；
    
*   页面滚动位置。
    

用户1天内返回AI页面后应恢复原对话，而不是重新显示AI欢迎页。

#### 2.4.5 回答原则

AI回答保持：

**短、准、可继续操作。**

避免在聊天窗口输出大段房地产分析文章。

建议普通回复控制在：

**50～150字。**

详细业务信息使用：

楼盘卡片；

政策卡片；

详情页

承载。

#### 2.4.6 AI限制

自行编造不存在的楼盘；

自行编造楼盘价格；

自行编造剩余房源；

自行回答学区相关问题；

自行编造政策；

把过期政策描述为当前政策；

承诺房价上涨；

承诺投资收益；

使用“稳赚”“必涨”“最值得购买”等绝对化表达。

对于动态数据统一以业务系统查询结果为准。

#### 2.4.7 异常提示

用户发送问题后，应显示AI回复中状态，例如：

“安安正在帮你找……”

请求成功后替换为正式结果。

如果AI服务异常：

“安安暂时开小差了，请稍后再试。”

如果楼盘查询接口异常：

“楼盘数据暂时没有查询成功，请稍后重试。”

如果政策接口异常：

“政策数据暂时没有查询成功，请稍后重试。”
