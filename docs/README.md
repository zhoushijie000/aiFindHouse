- 每个紫色 AI 节点都提供真实 Markdown 文件入口；点击节点可在右侧查看输入、输出与约束，并在页面内阅读全文。
- 四个 HTML 已内嵌样式、流程数据和节点文档预览，无网络依赖。直接双击即可使用。原文件链接需保留 docs 文件夹与 HTML 的相对位置。
- 文件是产品流程与输出规格说明，不连接真实 AI、楼盘库或政策库。

## 职责边界

AI：理解意图、提取或转换条件、补问、说明真实查询结果、基于原文解读、生成候选问题。

系统：字段和条件校验、真实业务查询、排序与限制数量、政策时效计算、验证候选问题、构造业务卡片与真实页面路径、会话状态保存、异常与重试。

业务数据异常不等于零结果。任何候选推荐问题需经过真实数据校验后才能展示。每次楼盘 / 政策最多 5 条，推荐问题最多 3 个。普通回复建议 50–150 字。

## 建议契约与待确认口径

以下为流程细化建议，原需求未提供完整接口协议；节点文档中的字段名和 JSON 是建议输出契约，研发接入时应与真实接口对齐。

- 最小查询范围：由业务支持字段与查询规则配置。不将区域、预算等全部设为必填；明确楼盘名可查询，“帮我找房”需补问。
- 预算：“以内”与“以上”分别保留上限与下限；“左右”浮动范围未定义，应按显式配置或追问，不擅自定义；仅报数字时保留解释依据。
- 非标准需求：需要系统能力与真实数据支持。没有地图和点位，不生成虚假通勤结论。
- 当前与最新：当前仅用有效政策；最新按业务配置的发布时间或生效时间排序，必须同时标明时效状态。时间缺失应标为待核验。
- 政策解读：原文同时提出“可简单总结”和“不回答具体政策结论”，此流程按保守口径处理：仅忠实归纳已取得的正文，不补造补贴标准、条件，不作个体资格承诺。缺正文使用受限说明并提供真实详情入口。
- 普通结果的推荐问题也进行数据验证，延续需求整体准确性原则；不得静默修改原始硬性条件。
- 查询验证全部失败或无结果时，不生成凑数问题，保留手动输入入口。
- 页面 / 顾问跳转路径根据可信业务 ID 由系统映射；AI 仅引用已提供的 ID。
- 本轮仅覆盖新房及购房支持政策；管理端二手房引导配置不意味着本轮扩展二手房流程。

## 共用状态

发送问题后显示 AI 回复中状态；成功后替换结果。AI 异常、楼盘接口异常、政策接口异常分别提示，重试失败节点并保留条件。进入楼盘详情、政策详情或其他业务页面，保存历史问题、回答、卡片、推荐问题、当前条件与滚动位置；1 天内返回恢复对话。

流程图中的“下一轮”携带上下文回到意图识别；业务不变时进入条件提取，仅覆盖本轮明确修改的条件。任一 AI 节点异常进入公共异常分支；可选追问 H07 / P07 生成失败时，隐藏推荐问题但保留已成功的说明和结果。

## 未识别意图时的系统固定引导

结合有效上下文仍未识别到意图时，系统原样返回以下文案，不调用 AI 生成或改写：

> 安安是你的购房小助手，我可以帮你找成都新房，以及查询成都购房支持政策。你可以告诉我想买哪个区域、预算多少，或者想了解哪类购房支持政策。

保留会话，等待用户继续提问；本轮不进入业务查询。AI 服务异常与未识别意图分别处理。

## 新增独立解读流程

- 楼盘解读对应 PROJECT_QUERY，先确认具体项目，再解释实时业务字段。对象不明确需确认，资料不足使用受限说明。
- 政策解读对应 POLICY_INTERPRET，先确认政策与版本，再核验原文及有效期。无完整正文使用系统固定受限说明，不补写条件和金额。
- 既有查政策流程保留查询结果的概要说明与简短解读环节；新政策解读页展示从指定政策到原文校验、引用核验的完整独立过程。
- 四类意图遵循 [共用意图识别 Prompt](house/H01-intent.md)。跨业务路由承接上下文，进入对应流程的对象 / 条件提取；直接提问时从该流程意图识别开始。
- 新增对象消歧、引用逐项核验、推荐验证及失败降级为基于原规则的细化建议，尚未连接真实业务接口。
