# I02 · 政策对象与解读问题提取

> 建议输出契约。示例政策引用为演示数据。

## 职责与触发

已识别政策解读意图后，提取指定政策、区域、版本线索、上下文指代与解读关注点。系统 IRES 负责匹配真实政策 ID，不能凭相近标题自动选中政策。

## 输入

- 用户原文、上轮政策卡片顺序与有效引用、已选择政策。
- 系统提供的政策字典能力与版本信息；用户本轮明确的名称、区域、时间。

## AI 输出 JSON 示例

```json
{
  "node_id": "I02",
  "target": {
    "provided_policy_ref": "demo-policy-a",
    "name_text": null,
    "region_text": null,
    "version_text": null,
    "reference_basis": "selected_policy_card"
  },
  "focus": ["application_conditions"],
  "original_question": "这项政策的申请条件是什么？",
  "target_changed": false,
  "unresolved": [],
  "next_node": "IRES"
}
```

## 字段说明与约束

- `provided_policy_ref` 仅引用业务系统已提供 ID；名称、区域、版本来自用户原文或可追溯上下文。
- “第一个政策”依据已展示卡片顺序解析，不能根据新排序重新绑定。
- 关注点可为概况、适用对象、条件、有效期、流程等；只识别问题，不推断答案。
- 用户粘贴片段可作为匹配线索，不自动当作完整有效政策原文；需业务库获取完整正文。
- 唯一匹配进 IQ；多版本、重名或指代不明进 I03；真实零匹配进 INF；对象匹配接口异常进 IMATCHERR，重试匹配。详情接口异常进 IE1，重试详情获取。

## 失败处理与验收

AI 故障不覆盖已确认政策。两区政策同名时需确认区域；用户明确指定历史版本时保留版本；旧政策被删除时重新查库，不引用缓存得出当前结论。

## 依据

需求 §2.4.3 政策查询条件、时间与政策准确性；§2.4.4 会话保持。对象及版本消歧为独立解读流程的建议补充。
