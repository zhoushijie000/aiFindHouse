# I03 · 政策对象确认追问

> 建议输出契约。业务意图已经明确，当前仅确认政策对象。

## 职责与触发

系统不能唯一确认政策时，询问名称、区域、版本或请用户从真实候选中选择。一次只问完成匹配所必需的信息。

## 输入

当前解读问题、已知政策线索、系统匹配候选、歧义原因及已有上下文。

## AI 输出 JSON 示例

```json
{
  "node_id": "I03",
  "question": "你想了解哪项政策？可以告诉我政策名称，或选择已经查到的政策卡片。",
  "candidate_refs": [],
  "awaiting": "policy_target",
  "preserve_focus": ["overview"],
  "next_node": "IU1"
}
```

## 字段说明与约束

- `candidate_refs` 只能来自 IRES 真实查询；名称、区域、时效等字段由系统渲染，AI 不创建候选政策。
- `question` 不预设补贴金额、资格、申请条件；未确认对象前不启动正文解读。
- 多版本需说明可核验的区分点，不能默认为最新版本后忽略用户原问。
- 保留原解读关注点，用户补充后回 I02/IRES；已知名称但零匹配使用 INF 固定提示。

## 失败处理与验收

AI 失败走 IE2；无对象时不输出政策结论；区域已确认则不重复问区域；用户选定后只解读该政策，不能拿另一政策替代。

## 依据

需求 §2.4.3 政策查询条件与准确性、§2.4.4 上下文保持。对象确认是本次细化建议。
