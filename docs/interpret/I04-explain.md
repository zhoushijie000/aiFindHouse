# I04 · 基于完整政策原文解读

> 建议输出契约，沿用 P05 的事实与资格边界。以下输入与输出为虚构测试数据，不代表任何真实政策。

## 职责与触发

系统已确认唯一政策、核验时效与来源，并取得完整可读正文后，按“结论 + 注意事项 + 原文入口”组织简短解读。结论指正文摘要，不代表用户个人资格或权利认定。

## 输入

- 已确认政策 ID、标题、标签、发布时间、有效期、系统计算的生效状态。
- 完整原文及可核验段落引用、发布机构、真实原文或详情路径引用。
- 用户当前问题、解读关注点；不以用户自述代替资格审核。

## AI 输出 JSON 示例

演示全文仅为两句：“本测试文件用于说明政策信息查询流程。”“阅读政策信息时应核对文件标注的有效期。”

```json
{
  "node_id": "I04",
  "policy_ref": "demo-policy-a",
  "mode": "body_summary",
  "status_ref": "demo-system-status",
  "conclusion": "示意政策 A 是说明政策信息查询流程的测试文件。",
  "notes": ["阅读时应核对文件标注的有效期。"],
  "claims": [
    {"text": "说明政策信息查询流程", "section_refs": ["demo-section-01"]},
    {"text": "核对文件标注的有效期", "section_refs": ["demo-section-02"]}
  ],
  "source_route_ref": "demo-original-route",
  "individual_eligibility": "not_assessed",
  "next_node": "ICHECK"
}
```

## 字段说明

| 字段 | 说明 |
| --- | --- |
| `mode` | 仅 body_summary，前置条件为完整正文。 |
| `status_ref` | 引用系统计算的时效状态，模型不自行改写状态。 |
| `conclusion` / `notes` | 必须由正文直接支持，不加入推测的标准或条件。 |
| `claims` | 每条事实绑定当前原文段落，供 ICHECK 核验。 |
| `source_route_ref` | 原文或详情路径的真实引用，不让模型拼接链接。 |
| `individual_eligibility` | 固定 not_assessed，不承诺用户能领取补贴。 |

## 约束与系统衔接

- 无正文或仅有片段：不调用 I04，由 ILIMIT 固定说明“当前可以查询到该政策，但具体补贴标准和申请条件需要进入政策详情查看。”
- 有正文但未提及用户所问条件时，明确原文未说明，保留原文入口；不从其他政策或常识补全。
- 原文明确的对象、日期、金额、条件和限制必须完整保留，不省略限制后得出夸大结论。
- 已失效与尚未生效的政策明确标识；历史解读不能描述为当前执行。
- 不回答学区归属，不作审核结果、个人资格或收益承诺。
- 原文内部矛盾或时效冲突需待核验，不自行裁决；无有效原文入口不编造链接。
- 普通回复建议 50–150 字；原文细节通过详情页承载。输出必须经 ICHECK 校验，通过后进入 I05；失败转 IREJECT/ILIMIT。

## 失败处理与验收

正文接口失败走 IE1，区别于成功读取但无正文。AI 服务错误走 IE2。无依据断言被拦截并转受限说明。测试“只有标题、没有正文”不得调用 I04；问“我一定能拿到吗”不承诺；原文没有材料清单时不生成材料清单。

## 可复用提示词与依据

只归纳当前完整正文。所有结论和注意事项都应有段落依据，保留生效状态及适用限制，不补造标准，不评定个人资格。输出供系统核验的 JSON。

依据：需求 §2.4.3 政策解读、准确性与时效；§2.4.5—2.4.7；本次独立政策解读流程要求。
