# I01 · 政策解读意图识别

> 建议输出契约，复用共用 H01 四类意图定义，示例不包含真实政策结论。

## 职责与触发

用户希望理解具体政策、条款或已选政策的条件时识别为 `POLICY_INTERPRET`。询问“有哪些政策”属于 `POLICY_QUERY`。找房与咨询具体项目分别为 `FIND_HOUSE` 和 `PROJECT_QUERY`。

## 输入

当前问题、必要历史上下文、当前政策选择、有效政策引用。完整语义规则见 [共用意图识别 Prompt](../house/H01-intent.md)。

## AI 输出 JSON 示例

用户在选定政策后问“这项政策需要满足什么条件？”：

```json
{
  "node_id": "I01",
  "intent": "POLICY_INTERPRET",
  "multi_intent": false,
  "need_clarification": false,
  "next_node": "I02"
}
```

## 字段、路由与约束

- `intent` 只能为四类意图之一或 `null`；本流程进入 I02。
- 多个独立业务目标遵循共用 Prompt 主、次意图规则，由系统安排后续路由。
- 问“我符合条件吗”可以识别为政策解读，但不表示系统具备个人资格认定能力，后续不作资格承诺。
- 意图识别不回答补贴金额、申请标准或政策事实。
- “解读一项政策”已明确业务，只是未指定对象，进入 I02/I03。

## 未识别意图：系统固定引导

结合有效上下文仍未识别到意图时，`intent` 返回 `null`，由系统 IG 原样返回以下文案，不调用 AI 生成、改写或补充：

> 安安是你的购房小助手，我可以帮你找成都新房，以及查询成都购房支持政策。你可以告诉我想买哪个区域、预算多少，或者想了解哪类购房支持政策。

## 失败处理与验收

- 结构无效或 AI 服务失败走 IE2，不当作意图未识别。
- “成都有哪些购房补贴” → POLICY_QUERY，进入查政策流程。
- “刚才第一条的申请条件” → POLICY_INTERPRET，保留候选引用后解析。
- “这个怎么样”且无上下文 → null，系统固定引导。

## 依据

H01 四类意图定义；需求 §2.4.1、§2.4.3；本次新增独立政策解读流程与固定引导要求。
