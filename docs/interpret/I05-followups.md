# I05 · 政策解读后推荐追问

> 建议输出契约；示例为虚构测试引用。推荐最多 3 个，先验证后展示。

## 职责与触发

ICHECK 校验通过或 ILIMIT 返回固定受限说明后，依据政策正文可用性及真实操作入口提出下一步候选。不因用户已进入解读流程就假定存在正文。

## 输入

当前政策、用户问题、已解读内容、完整正文可用性与段落索引、有效原文/详情路径、系统可支持查询能力。

## AI 输出 JSON 示例

测试正文只有政策信息阅读注意事项时：

```json
{
  "node_id": "I05",
  "candidate_questions": [
    {
      "question": "这项政策信息还有哪些阅读注意事项？",
      "policy_ref": "demo-policy-a",
      "requires_full_body": true,
      "supporting_sections": ["demo-section-02"],
      "verification_state": "pending_system_query"
    }
  ],
  "next_node": "IV"
}
```

## 字段说明与约束

- `candidate_questions` 可为空，不凑数；不重复当前已回答问题。
- `supporting_sections` 必须引用真实正文，IV 再次核验正文是否支持该追问。
- 缺正文时不推荐额度、条件或资格解读，只保留真实详情入口或可查询到数据的查政策操作。
- 原文未记载申请材料、途径、金额时，不生成相关问题诱导用户期待不存在的答案。
- 用户点击后进入 I01/I02 并继承政策引用；改问其他政策或业务时重新匹配、重新路由。
- 验证接口失败或零通过时隐藏推荐问题，保留本轮解读；新问题提交时重新获取需要的实时信息。

## 失败处理与验收

推荐生成失败不能清空已成功的政策解读。只有两条通过就显示两条；缺正文不能推荐申请标准解读；详情路径失效时隐藏入口，不拼接假链接。原文页面 1 天内返回，恢复政策对象、解读、卡片、追问和滚动位置。

## 依据

需求 §2.4.1 后续问题、§2.4.3 政策真实数据与零结果原则、§2.4.4—2.4.7；本次独立解读流程补充。
